# ADR-002: LEB128 は、手書きのテストに加えてプロパティテストで検証する

## 課題

LEB128 は可変長の整数で、オーバーフロー・不正な終端ビット・境界など、エッジケースが多い。
手で書いたテストでは、境界の値を取りこぼしやすい。

## 決定

ユニットテストに加えて、`proptest` で次の性質を検証する。

- 任意のバイト列とオフセットに対して、LEB128 のデコーダー（u32 / i32 / i64）と `section_iter`、`parse_module` がパニックしない。
- 正しい LEB128 でエンコードした値は、同じ値にデコードされる（u32 と i32 の往復）。エンコーダーはテスト専用に持つ。

## 理由

- ランダムな入力は、手で書いたケースでは見つかりにくい境界の誤りを、継続的に検出できる。
- **却下した代替案:** 比較した記録はない（当時の検討は未確認）。

## 影響

- 往復の検証は u32 と i32 だけで、i64 は「パニックしない」検証のみ。往復の検証の範囲は広げられる。
- 仕様への適合性（公式のテストスイートに通るか）は、この検証では測れていない。

## 再検討条件

公式の仕様テストスイートを導入するとき、または i64 の往復を足すとき。
